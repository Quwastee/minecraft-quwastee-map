# Contributing to Quwastee Map

Thank you for your interest in contributing to **Quwastee Map**.

Contributions should keep the project stable, understandable, and focused on improving the map and its supporting systems.

---

## 🧭 Before You Start

For larger changes, open an issue first so the direction can be discussed before implementation.

Small fixes, documentation improvements, and clearly scoped changes can be submitted directly through a pull request.

---

## 🔧 Pull Requests

A good pull request should:

- have a clear purpose;
- keep unrelated changes out of the same pull request;
- avoid unnecessary breaking changes;
- update documentation when project behaviour changes;
- update version or compatibility information when required;
- include a changelog entry for user-facing changes.

---

## 🗺️ Map Changes

When changing map content, explain what area or gameplay element was changed and whether the change affects progression, exploration, or compatibility.

Large world or content changes should be described clearly so they can be reviewed and documented properly.

---

## 🧩 Quwastee API Changes

When a change depends on or modifies interaction with Quwastee API, document:

- the required API version;
- why the dependency is needed;
- whether another API version is supported.

---

## 🐛 Bug Reports

Use GitHub Issues to report bugs whenever possible.

Include:

- Quwastee Map version;
- Minecraft version;
- relevant environment information;
- reproduction steps;
- expected behaviour;
- actual behaviour;
- logs or screenshots when relevant.

---

## 💡 Feature Requests

Feature requests should describe the problem, the proposed idea, and why the change would improve the project.
